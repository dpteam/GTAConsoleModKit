Осознанные решения и границы:

1. **g3DTZ переписан, а не слинкован**: C++-логика (relocatable chunk, `CStreaming`,
   `CPool`, TexListDef) реализована в `Formats/Rsl.cs` + `Formats/Dtz.cs`. Читать чанк
   можно без релокации: в файле указатели уже лежат как смещения.
2. **VCS таблица стриминга — разобрана.** Причина старой ошибки: у VCS `pos/size` стоят
   в начале 20-байтной записи (у LCS — в конце), а массив начинается на 12 байт позже
   указателя. Сверка с чанками IMG: 310/310. `dtz-dir` работает для обеих игр,
   имена моделей/текстур разрешаются полностью (0 `HASH_*` на VCS USA).
3. **Запись текстур** сделана для pal4/pal8. Не сделана для 16/32bpp и DXT
   (нужен упаковщик DXT; декодер уже есть) и mip-цепочка для pal4.
4. **PMF/AT3/SCM/Lua** — только идентификация и метаданные (декодеры вне BCL).
5. **Доступ**: по умолчанию сервер слушает `0.0.0.0`, но пускает с других машин только
   по токену (`bin\auth.token`, печатается при старте; `127.0.0.1` — без токена).
   `exposure=session` оставляет по сети только работу с проектами. Входящее правило
   Windows Firewall добавляет `tools/firewall.cmd` (UAC, порт из `config.ini`, только
   приватные адреса). Наружу — через reverse proxy и `exposure=session`.

## Состояние на текущую итерацию

Сделано (галерея текстур образа):

- **`GET …/img-textures`** — все текстуры всех чанков внутри IMG (для голого образа
  имена чанков синтетические из скана: `tex_000123`). **`GET …/img-texture`** — PNG одной
  текстуры с необязательным `w` (превью nearest-neighbour).
- **Кэш `ImgCache`** на файл: открытие IMG — полное сканирование, а галерея просит по
  картинке на плитку. Замеры на `GTA3PSPHR.IMG` (38.3 МБ): индекс **3 019 текстур /
  582 чанка за 0.52 с**, первое превью 48 мс, следующие ~34 мс.
- **В инспекторе**: у любого IMG — заголовок «Текстуры (N)», фильтр по имени текстуры
  или чанка, страницы по 120 плиток («Показать ещё»), клик → полный PNG. Проверено на
  живом LCS: лицо Тони, копы, ткани — 120 из 3019, фильтр `toni` даёт 255.
- **`inspect` теперь сообщает `imgEntries`**: упакованный IMG может начинаться с чанка
  `xet` и выглядеть как CHK, поэтому галерея включается по числу записей, а не по типу.
  Одиночный CHK по-прежнему показывает старую сетку.
- **`ImgArchive` больше не падает** на не-архиве: скан в `try/catch`, «raw (no index)»
  вместо исключения (это ловил тест на текстовом файле).

Сделано (образ из проекта одной кнопкой):

- **`POST /api/projects/{id}/build`** → задание `build-project`: дерево игры + `files/`
  проекта → ISO/CSO (тот же `Operations.BuildImage`, папка правок = проект). Пустой
  `target` = `export/<id>.iso|.cso`. Запись `build` в журнал, рассылка участникам.
- **В морде** — панель «Собрать образ из проекта» в «Операциях»: дерево, куда писать,
  CSO, метка тома; сводка «Файлов: N, X заменят дерево»; последнее дерево запоминается
  в `localStorage`.
- Проверено на маленьком дереве (2048 → 3000 байт override): файл внутри ISO побайтово
  равен файлу проекта, задание `done`, ISO читается `iso-extract`.
- Грабли: в PowerShell `$base` и `$Base` — одна переменная, и тест затёр адрес API
  («имя содержит недопустимый символ»); переименовал в `$tree`.

Сделано (доступ по сети):

- **Токен для не-loopback запросов**: `bin\auth.token` (генерируется при первом старте,
  печатается в консоль и в лог), заголовок `X-DPT-Token` или `?token=`; сравнение без
  раннего выхода. `127.0.0.1` — без токена. `/api/health` открыт всем (мониторинг).
- **`exposure=full|session`**: `session` по сети оставляет только проекты
  (файлы/журнал/заметки/загрузка), режет `/api/fs`, `/api/ops`, `/api/identify`,
  `/api/logs`, `/api/status`, `folder/mkdir/delete` и удаление проекта.
  Проверено на живом сервере с LAN-адреса: `/api/fs` и `/api/ops` → 403, проекты → 200,
  loopback → по-прежнему всё.
- **Морда**: полоска «нужен токен» появляется на первом 401, токен хранится в
  `localStorage`, для `<img>`/`<audio>` подставляется в query. После сохранения —
  перезагрузка данных, ошибок в консоли нет.
- **Тесты**: 3 новых (`401` с другого адреса, `200` с токеном, `/api/health` открыт).

Сделано (папки: сервер и клиент):

- **Проводник по файлам сервера** (`GET /api/fs`) + панель в веб-морде: корни списком,
  переход по папкам, хлебные крошки, «Добавить эту папку». Последний путь запоминается
  в `localStorage`.
- **Загрузка папки с клиента** («+ С ПК», `webkitdirectory`): браузер читает папку у себя
  и заливает файлы по одному с сохранением структуры (`webkitRelativePath`).
  Это единственный способ принести файлы, которых сервер не видит: диск `T:` на клиенте
  для сервера не существует.
- **Корни чтения**: `workspace`, `gamesRoot`, `workspace.roots` (новый ключ).
  Пусто = папка набора целиком.
- **Сравнение путей по идентичности файла** (серийник тома + индекс), а не по строке:
  `X:\refs` через subst, junction и сетевой share распознаются как тот же каталог.
  Проверено: `subst X: <toolkit>` → `X:\refs\temp` принят и канонизирован в `E:\...`.
  Диск, примонтированный только у клиента, честно получает `403` со списком корней.
- **Read-only файлы**: `File.Copy` сохраняет атрибуты, поэтому скопированный в проект
  git-пак оставался read-only и ломал и правку, и удаление. Теперь копии делаются
  writable, а `delete` чистит атрибут по дереву (`Util.DeleteTree`).

Сделано (дерево проекта + CI):

- **GitHub Actions** (`.github/workflows/build.yml`) по образцу AdHoc: `windows-latest`,

  в трёх темах.
