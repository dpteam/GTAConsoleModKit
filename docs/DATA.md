# Данные игры в `refs/`

Всё в `refs/` **не попадает в git** (см. `.gitignore`) — это рабочий материал: распакованные
данные образов и реверс-наработки. Инструмент без них полностью собирается, а тесты форматов
просто пропускаются, если данных нет.

## Что где лежит (после уборки)

```
refs/GAMES/extracted/<slug>/PSP_GAME/...   распакованные данные образов — это и есть «образ»
refs/GAMES/extracted/LCS, .../VCS          RUS-переводы
refs/GAMES/MANIFEST.md                     отчёт: что было, что идентично, что удалено
refs/GAMES/manifest.json                   то же в машинном виде (SHA-256, DISC_ID, размеры)
refs/ReverseMe/                            дампы REA по утилитам (txdworkshop, GGMM, конвертер карт)
refs/Also/                                 чужие тулзы и их исходники (для сверки форматов)
refs/g3DTZ, refs/cso-to-iso                референсные репозитории
```

Архивов `.7z/.zip` и файлов `.iso/.cso` в `refs/GAMES` больше нет: после проверенной
распаковки они удалены (место), а **SHA-256 каждого образа сохранён в манифесте** — по нему
всегда видно, что именно было разобрано и какие образы совпадали.

## Как это получается

```bat
python tools\import_games.py                  :: разобрать архивы (1 раз на папку)
python tools\prune_games.py --delete-images --delete-archives
                                             :: хеши данных, удаление дублей и мусора
```

`import_games.py` для каждого архива:

1. распаковывает во временную `_work/`;
2. если внутри CSO/ZSO — разжимает **своим же** конвертером (`ModKit.exe cso`);
3. считает SHA-256 образа и сравнивает с уже виденными (побайтовые дубликаты образов
   удаляются сразу);
4. распаковывает `PSP_GAME` в `extracted/<slug>/`, читает `DISC_ID`/`TITLE` из `PARAM.SFO`;
5. пишет манифест после каждого образа — прогон можно прерывать и продолжать.

`prune_games.py` считает два отпечатка на каждую папку:

| Отпечаток | Что покрывает | Зачем |
|---|---|---|
| `dataSha256` | `PSP_GAME/USRDIR` (игровые данные) | **именно это** определяет «одинаковые образы» |
| `treeSha256` | всё дерево `PSP_GAME` (включая `EBOOT.BIN`) | версии прошивки отличаются именно им |

Папки с одинаковым `dataSha256` — дубликаты данных: остаётся одна, остальные удаляются и
попадают в отчёт.

Почему не только хеш ISO: разные версии одной игры (v1.05 / v2.00 / v3.00) почти всегда
имеют разный `EBOOT.BIN`, но одинаковый `USRDIR`. Хеш ISO показал бы «всё разное», а
пользователю нужно знать как раз обратное.

## Правила уборки

- **Удаляется:** архивы `.7z/.zip`, промежуточные `.iso/.cso`, дублирующиеся деревья данных.
- **Остаётся:** по одному дереву на уникальный набор данных + манифест с хешами.
- Порог свободного места в импортёре — 6 ГБ: прогон останавливается, а не забивает диск.

## Чем пользоваться

Тесты (`tools/test-formats.ps1`) и примеры в документации ссылаются на
`refs/GAMES/extracted/LCS` и `.../VCS` (RUS-переводы). Оригинальные образы нужны для:

- сверки форматов на «чистых» данных: именно по ним удалось выяснить, что у VCS поля
  `pos/size` стоят в начале записи стриминга (у LCS — в конце), а массив начинается на
  12 байт позже указателя;
- региональных различий (EU/US/JP/KR/DE): текст, аудио, порядок ассетов;
- версий (v1.05/v2.00/v3.00): по манифесту видно, какие из них отличаются только
  загрузчиком, а какие — данными.

## Атрибуция и правовое

Образы игр — собственность правообладателей, в репозиторий не входят и в нём не
распространяются. Инструмент не содержит игровых данных; всё, что он делает, — читает и
пишет файлы, которые пользователь предоставил сам.
