# Сессии и совместная работа

## Модель

Проект — это папка в `workspace/`. У проекта есть **код сессии** вида `ABCD-2345`
(алфавит без `0/O/1/I`, чтобы код можно было продиктовать голосом).

Режимы:

| Режим | Как работает | Что синхронизируется |
|---|---|---|
| **оффлайн** | папку проекта переносят на другую машину | всё, потому что всё в `project.json` + `files/` |
| **онлайн** | оба человека на одном сервере, второй подключается по коду | журнал операций и список участников |

Сервер — единственный источник правды, пока он запущен. `project.json` на диске —
долговременная память: после перезапуска история и код остаются.

## Что такое «операция»

Каждое осмысленное действие пишется в журнал:

```json
{"seq": 12, "when": "2026-11-08 03:15:49", "user": "DartPower",
 "kind": "chk-export", "target": "textures/LOADSC0.CHK", "note": "exported 1 textures"}
```

- `seq` монотонно растёт (`nextSeq` в манифесте).
- `kind` — `create`, `import`, `join`, `note` или имя операции (`cso-to-iso`, `iso-extract`,
  `dtz-dir`, `chk-export`, …).
- Журнал хранит последние 5000 записей.

## Синхронизация: long-poll, а не WebSocket

`GET /api/projects/{id}/session/wait?activity=N&clientId=…&ms=15000` — сервер держит запрос
до 15 секунд и отвечает, как только `activity` изменилась (кто-то присоединился, ушёл,
добавил операцию). Клиент сразу открывает следующий запрос.

Почему так, а не WebSocket:

- работает через любой reverse proxy и на Windows XP без плясок;
- не нужен свой парсер кадров RFC 6455 и heartbeat-логика;
- при обрыве клиент просто повторит запрос через 4 секунды (уже реализовано).

Плата — до ~1 запроса в 15 секунд на участника, что для инструмента моддинга незаметно.

## Присутствие

`SessionHub` держит участников в памяти: `clientId`, ник, время входа и последней
активности, адрес. Участник считается ушедшим после 30 секунд молчания (`Prune`).
Присутствие **не** сохраняется на диск: перезапуск сервера = все вышли, история осталась.

Лимит: один и тот же `clientId` (он лежит в `localStorage`) входит один раз, повторный
`join` просто обновляет ник и время.

## Как подключиться

1. Оба открывают один и тот же сервер (`http://<ip>:44700/`).
2. Первый создаёт проект и получает код.
3. Второй открывает тот же проект (он виден в списке, потому что проект общий) —
   либо, если его нет на его машине, создаёт локальный и передаёт код вручную.
4. На вкладке **Сессия** вводит ник и жмёт «Подключиться».
5. Дальше оба видят участников, а журнал обновляется сам.

## Границы, о которых надо знать

- **Файлы сами не передаются.** Синхронизируется журнал и присутствие; сами бинарники
  каждый держит у себя (или загружает на сервер — тогда они в общей папке проекта).
  Автоматическая пересылка больших образов между клиентами — в `docs/ROADMAP.md`.
- **Нет блокировок файлов.** Двое могут одновременно править один файл; журнал покажет
  оба действия. Для моддинга это приемлемо, для «боевого» редактора — нет.
- **Нет авторизации.** Кто дотянулся до порта, тот и в сессии. Наружу — только через
  reverse proxy с авторизацией.
- **Код сессии — не пароль.** Это идентификатор комнаты; он не даёт доступа к серверу
  сверх того, что уже даёт сеть.

## API (кратко)

| Запрос | Смысл |
|---|---|
| `GET /api/projects/{id}/session` | код, участники, `activity`, `next` |
| `POST /api/projects/{id}/session/join` | `{nick, clientId}` → `clientId`, код |
| `POST /api/projects/{id}/session/leave` | `{clientId}` |
| `GET /api/projects/{id}/session/wait` | long-poll изменений |
| `GET /api/projects/{id}/ops?since=N` | операции после `N` |
| `POST /api/projects/{id}/note` | `{text, user}` — заметка в журнал |

Полный список — `docs/WEB.md`.
