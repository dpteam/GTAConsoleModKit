# Логирование

## Правила

1. **Только `Trace`.** Никаких `app.config`, `TraceSource` настраивается кодом при старте.
2. **Ровно два листенера.** Один файловый (полный verbose), один консольный (только важное).
   `Trace.Listeners` предварительно очищается, поэтому `DefaultTraceListener` (тот, что
   пишет в отладчик и в консоль) не участвует и дублей нет.
3. **Код не пишет в консоль для логов.** `Console.Write*` в проекте нет ни в одной
   подсистеме логов — консольный вывод делает только консольный листенер.
4. **Уровни независимы.** `logging.fileLevel` и `logging.consoleLevel` в `config.ini`.

## Формат

```
2026-11-08 03:15:49.895 [INF] JOB job-0001 chk-export started: chk-export
        │            │     │   └─ сообщение
        │            │     └───── категория
        │            └─────────── уровень (VRB/DBG/INF/WRN/ERR/FTL)
        └──────────────────────── локальное время с миллисекундами
```

Категории: `APP`, `CONFIG`, `NET`, `HTTP`, `API`, `FMT`, `JOB`, `FS`, `PROJ`, `SESS`,
`LOG`, `UI`, `FAULT`.

## Что видно в консоли

Консольный листенер пропускает:

- всё с уровнем `WRN` и выше (любая категория);
- `Info` и выше для `APP`, `CONFIG`, `NET`, `API`, `PROJ`, `SESS`, `FAULT`, `FS`.

Сознательно **не** выводятся: `FMT` (разбор форматов), `JOB` (пошаговая работа заданий),
`HTTP` (каждое соединение) — это десятки строк в секунду, они нужны только в файле.

## Файлы

```
logs/modkit-20261108.log       текущий день
logs/modkit-20261108.001.log   после 8 МБ
logs/modkit-20261108.002.log   ...
```

Хранится 5 файлов на префикс, старые удаляются при ротации. Файл пишется в UTF-8 и
открыт с `FileShare.ReadWrite`, поэтому его можно смотреть `tail`-ом, не останавливая сервер.

## Живой хвост в веб-морде

`Log` держит кольцевой буфер последних 500 строк (`Log.Tail`), его отдаёт `/api/logs`.
Страница «Лог» опрашивает его раз в 3 секунды. Читатели буфера получают только уже
записанные строки, так что UI не может повлиять на сам лог.

## Отладочные подсказки

- Проблема с форматом → поставьте `logging.fileLevel=Verbose`, в файле будут смещения,
  размеры чанков и причины отказов парсеров.
- Проблема с сетью/портом → `NET`/`HTTP` видны в консоли по умолчанию.
- Шум от браузера, закрывающего вкладку, уходит в `DBG` (`HTTP connection … closed early`),
  это не ошибка.

## Чего нет намеренно

- Нет отдельного «аудита безопасности» (аутентификации тоже нет).
- Нет отправки логов наружу: инструмент локальный, всё остаётся на диске.
