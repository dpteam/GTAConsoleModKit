# План развития

Порядок выбран так, чтобы каждый шаг опирался на уже проверенные кирпичи и не требовал
переделки готового. «PSP → PS2 → Chinatown Wars» — как в исходной постановке.

## Ближайшее (закрыть дыры первой версии)

1. **VCS: таблица стриминга.** Разобрать `CStreaming` VCS PSP по живому адресу
   (сейчас смещения сходятся по размеру, но содержимое не то). Результат: `dtz-dir` для
   VCS, имена моделей и `*_unpacked` без сканирования.
2. **DIR из LVZ.** `.DIR` для district-IMG (COMMER/INDUST/SUBURB/UNDERG у LCS,
   BEACH/MAINLA/MALL у VCS) лежит внутри `.LVZ` → `WRLD`-чанка. Нужен разбор `WRLD`
   (директории + streaming infos района). Это даёт полный список моделей карты, а не
   только «глобальные» ~500.
3. **Запись текстур.** Палитра + swizzle + генерация mip-цепочки → упаковка PNG обратно
   в `.CHK`. Тогда замена текстур станет полным циклом: `CHK → PNG → правка → CHK → IMG → ISO → CSO`.
4. **Пересборка IMG с обновлением стриминга.** Сейчас IMG собирается, но `GAME.DAT`
   остаётся со старыми смещениями. Нужен пересчёт таблицы стриминга при изменении размеров.

## Дальше (функциональность моддинга)

5. **Модели**: чтение геометрии MDL (Rsl-структуры уже описаны в `Formats/Rsl.cs`),
   экспорт в DFF/OBJ, импорт с пересчётом блоков.
6. **Карта**: IDE/IPL из LVZ → текстовые форматы → обратно; импорт/экспорт объектов.
7. **SCM**: разбор LCS/VCS-скриптов, дизассемблер и сборка (Sanny Builder-совместимый вывод).
8. **Lua**: `.LUA.LC` — вытащить константы и строки; декомпиляция — внешним `unluac`.
9. **Аудио**: RAW/SDT-контейнеры PSP (сейчас только VAG по отдельности), банки SFX.
10. **GXT запись**: правка строк и сборка таблиц обратно.

## Конвертация платформ

11. **PSP ↔ PC**: MDL ↔ DFF, CHK ↔ TXD, IMG ↔ IMG (III/VC), тайминги, ограничения
    палитры PSP (4/8bpp) — предупреждения и авто-квантование.
12. **PS2**: `GAME.DTZ` PS2 (4-байтные `bool`, другие смещения `sResourceImage`),
    PS2 TXD/DFF. Начинается с обобщения таблицы смещений в `Dtz.cs`.
13. **Chinatown Wars** (задача со звёздочкой): другая платформа (DS/PSP-порт), свои
    контейнеры; потребует отдельного набора парсеров.

## Инфраструктура

14. **Пересылка файлов между участниками сессии** (сейчас общий только журнал).
15. **Аутентификация** для `bind=0.0.0.0` (токен + подпись запросов, как в AdHoc).
16. **WebSocket** вместо long-poll, если появятся сотни одновременных участников.
17. **Пакетные пресеты**: «распаковать полностью», «собрать обратно», «заменить
    текстуру и пересобрать образ» одной кнопкой.
18. **CI**: GitHub Actions — `windows-latest`, `tools\ci-test.ps1`, артефакт `bin\`.

## Что осознанно не планируется

- Встроенные декодеры ATRAC3+ и MPEG (PMF). Это отдельные большие библиотеки; разумнее
  вызывать `ffmpeg`/`at3tool` и документировать это.
- Полноценный 3D-вьюер в веб-морде: инспектор показывает текстуры и таблицы, превью
  геометрии — задача отдельного инструмента.
- Поддержка читерских/онлайн-модификаций: набор про ассеты и данные, не про память игры.
